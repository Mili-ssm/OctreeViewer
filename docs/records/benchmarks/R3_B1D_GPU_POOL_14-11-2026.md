# R3 B1d: pool de celdas de 512 MiB y corte ajustado al pool — 14-11-2026

**Estado: pasa.** En Chrome con WebGPU sobre la Radeon 880M, con el pool de 512 MiB del
[ADR 0040](../../adr/0040-pool-de-512-mib-y-corte-ajustado-al-pool.md), **se asientan las 14 poses**
de Belvedere y Majadas a 1 px y a 4 px. Belvedere a 1 px tras un salto, que antes retenía el corte
anterior durante 282 s por desbordar el pool ([B1c](R3_B1C_CPU_FIT_14-11-2026.md#belvedere-a-1-px-tras-el-salto)),
ahora aplica su corte. El GTT pico sube de ~+430 a ~+750 MiB sobre el reposo.

## Qué cambió

| Cambio | Detalle |
| --- | --- |
| Pool | 512 MiB de instancias, o lo que admita el adaptador, con 256 MiB como mínimo (si no, ruta CPU). En la Radeon 880M queda en **65.535 páginas**, no 65.536: el pase de ranuras lanza un grupo de trabajo por página y el límite habitual por dimensión es 65.535 |
| Presupuesto propio del pool | `cell_pool_budget_bytes` = 660 MiB por defecto: el pool completo (instancias, índices visibles, bits de visibilidad y tabla de páginas) ocupa ~655 MiB, con ~5 MiB de margen. El presupuesto de GPU compartido no cambia. Los bytes del Hi-Z no entran en este presupuesto |
| Corte de nodos ajustado al pool | El planificador cuenta las páginas del nivel más grueso de cada nodo del corte, del soporte y de los hijos en curso, y bloquea como el ajuste de CPU (90/80, [ADR 0039](../../adr/0039-hijos-en-curso-y-bloqueo-retenido.md)). Contador `gpuCoarsened` |
| Bloqueo de un nodo que no cabe solo | Su tamaño queda en el bloqueo retenido, para que no se construya y se descarte en cada actualización |
| Tamaño del pool en el worker de construcción | Llega en cada apertura, también al recrear el worker; si falta con las celdas activas, el probe falla la pose (`gpuPoolPages` = 0) |

## Límites

- **El ajuste del corte al pool no actuó en el navegador** (`gpuCoarsened` = 0 en todas las poses):
  en estos datos basta con el pool mayor. Lo cubre un test en simulación: con un pool de 16 páginas el
  corte se asienta aplicado, con `gpuCoarsened` > 0 y `poolOverflow` constante
  (`a_pool_smaller_than_the_coarsest_levels_of_the_cut_settles_with_nodes_coarsened`). El bloqueo
  retenido de un nodo que no cabe solo tiene test para el presupuesto de CPU, no para el pool.
- Las poses «asentadas» a 1 px quedan engrosadas por el presupuesto de CPU, no por el pool.
- Una ejecución por caso, en un equipo, con Chrome 157 y Belvedere y Majadas v7.5.
- El intervalo entre frames está atado al vsync de 60 Hz; el tiempo de GPU no se midió.
