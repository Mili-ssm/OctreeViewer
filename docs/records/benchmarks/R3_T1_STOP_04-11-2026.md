# R3 T1: parada por profundidad en Majadas — 04-11-2026

**Estado: parada; T1 pendiente.** El diagnóstico de Majadas v7.5 señala 8.546 de 19.526 hojas al alcanzar el límite de profundidad de la cadena. De ellas, **16 tienen colisiones entre posiciones decodificadas `f32` distintas** y 8.530 solo presentan duplicados; no se observaron posiciones no finitas. La existencia de colisiones distintas activa el criterio de parada de T1. No se decide aquí cómo resolverlo.

## Evidencia y alcance

El [diagnóstico completo](data/r3-t1-stop-04-11-2026/diagnostic/output.txt) recorre las hojas, calcula la profundidad inicial a partir del espaciado y la celda en `first + CHAIN_SPAN`, y compara el número de celdas ocupadas con el de posiciones únicas decodificadas. Conserva ejemplos de 12 de las 16 hojas con colisiones distintas. La [comprobación de una hoja](data/r3-t1-stop-04-11-2026/diagnostic/one-output.txt) muestra un duplicado en el nodo `1640677507082`: 62.626 puntos, 62.625 posiciones y celdas únicas.

La [prueba directa del constructor](data/r3-t1-stop-04-11-2026/diagnostic/proof-output.txt) confirma en el nodo 19 dos posiciones distintas en la misma celda de profundidad 14 con el espaciado guardado de 16. Al usar espaciado 8 exclusivamente para el diagnóstico, el constructor expone dos celdas distintas en profundidad 15. Esta variación sirve para inspeccionar el nivel siguiente; no es una solución propuesta.

«Distintas» y «duplicadas» se refieren a los bits de las coordenadas locales `f32` tras la decodificación, normalizando el cero con signo; no demuestran si las coordenadas originales de entrada eran idénticas. El conteo se refiere a este dataset y a la implementación capturada, no a otros datasets. El stdout completo del benchmark original no se conservó: su resultado no es la fuente de los recuentos anteriores. Una comprobación concurrente afectaba al entorno; no se hacen afirmaciones de rendimiento.

## Reproducción e identidad

El dataset medido es `target/render-data/majadas-v75.oct`, SHA-256 `269d5df1e6da8485a0fd5ded3798a0f79bdde61ff298f624e5497dba6b29f1b1`; su `.octattrs` tiene SHA-256 `cc253c28ff90b1d5361f5cdb781217f5d1d78b809b1736298066f16c7149b3fd`. No se incluyen los datasets por su tamaño. Los [fuentes, manifiesto, lockfile, comandos y salidas](data/r3-t1-stop-04-11-2026/diagnostic/) del diagnóstico se conservan íntegros. Los comandos originales usan `target/r3-cap-diagnostic`; para repetir sin sobrescribirlos, desde la raíz del repositorio:

```sh
mkdir -p target/r3-cap-diagnostic-repro
cp -r docs/records/benchmarks/data/r3-t1-stop-04-11-2026/diagnostic/. target/r3-cap-diagnostic-repro/
CARGO_TARGET_DIR=target cargo run --manifest-path target/r3-cap-diagnostic-repro/Cargo.toml --bin r3-cap-diagnostic --profile perf --offline -- target/render-data/majadas-v75.oct > target/r3-cap-diagnostic-repro/recheck.txt
CARGO_TARGET_DIR=target cargo run --manifest-path target/r3-cap-diagnostic-repro/Cargo.toml --bin one --profile perf --offline -- target/render-data/majadas-v75.oct > target/r3-cap-diagnostic-repro/one-recheck.txt
CARGO_TARGET_DIR=target cargo run --manifest-path target/r3-cap-diagnostic-repro/Cargo.toml --bin proof --profile perf --offline -- target/render-data/majadas-v75.oct > target/r3-cap-diagnostic-repro/proof-recheck.txt
cmp target/r3-cap-diagnostic-repro/output.txt target/r3-cap-diagnostic-repro/recheck.txt
cmp target/r3-cap-diagnostic-repro/one-output.txt target/r3-cap-diagnostic-repro/one-recheck.txt
cmp target/r3-cap-diagnostic-repro/proof-output.txt target/r3-cap-diagnostic-repro/proof-recheck.txt
```
